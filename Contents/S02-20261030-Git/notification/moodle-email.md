This week, Siyuan He (何思源, Robert) will give an introduction to Git — how it works under the hood and how to use it in practice.

Part 1: From Saving Files to Building History

Do you have files like main.py, main_old.py, main_final.py, and main_final_really_final.py in your project folder? Have you ever wanted to go back to the version that worked three days ago, only to find that it is gone?

In this part, Siyuan will start from the question "why do we need version control at all?" and build a mental model of the working tree, the staging area, and the repository — entirely through the VS Code graphical interface, with no command line required. He will also take a look under the hood: what exactly does Git save each time you click "Commit"?

Part 2: From Branches to Distributed Collaboration

Do any of these sound familiar?

You want to try a new algorithm but are afraid of breaking the working version, so you end up copying the whole project folder as a backup.

You hear people say "just create a branch", but you have no idea what a branch actually is.

When push or pull fails, you have no clue what Git is trying to tell you.

In this part, Siyuan will explain what branches really are, how merging works (and why conflicts are not scary), how to undo a wrong commit, and how your local repository talks to GitHub — what push, fetch, and pull actually move.

I hope this weekly session will help you build a solid mental model of Git, never lose a working version again, and make your first group project much smoother 😈

Whether you are a complete beginner or simply want to exchange technical ideas, you are welcome to join us!
